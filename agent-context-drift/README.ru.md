# agent-context-drift

**Инструкция для агента — это код. Её надо линтить как код.**

`CLAUDE.md`, `AGENTS.md`, `.cursorrules` — файлы, которые объясняют ИИ-агенту,
как устроен ваш репозиторий. Потом вы переименовываете папку, удаляете файл,
переносите скрипт — и никто их не обновляет.

Устаревший README раздражает человека: он замечает несоответствие и идёт
смотреть сам. Устаревшая инструкция **меняет поведение агента**. Он идёт по
мёртвому пути с полной уверенностью, открывает прошлогодний план вместо
текущего и старательно воспроизводит тот самый бардак, который его просили
разобрать. Глазами это не увидеть: файл выглядит осмысленно, пока не проверишь
каждый путь.

Здесь проверяется каждый путь. Без LLM, без сети, без токенов: три секунды,
JSON-отчёт и число.

```console
$ agent-drift --explain

------------------------------------------------------------------------
docs/AGENTS.md   drift 65.5 [broken]   lag 68.0d · 34 changes since
    BROKEN:
      line   91  docs/skills_catalog.md   [not_found]
      line  185  docs/sla.md              [not_found]
    undocumented:
                 reports/
```

## Два способа запустить

**Скриптом.** Забираете один файл и запускаете. Ставить нечего: только
стандартная библиотека, Python 3.9+.

```bash
curl -O https://raw.githubusercontent.com/Voronik1801/candy-from-shipuchka/main/agent-context-drift/agent_drift.py
python3 agent_drift.py --explain
```

**Скиллом.** Кладёте `SKILL.md` в `.claude/skills/agent-drift/` и говорите
«проверь мои инструкции». Скилл прогоняет проверку, раскладывает находки по
корзинам *устарело* / *не описано* / *намеренно* / *непонятно*, предлагает на
каждую одно конкретное действие и ждёт подтверждения перед записью.

Намеренно не библиотека и не пакет в PyPI. Это никто не импортирует: его либо
запускают в пайплайне, либо отдают агенту.

## Использование

```bash
agent-drift                    # JSON по всему репозиторию
agent-drift --explain          # человекочитаемо
agent-drift --summary          # одна строка, молчит когда всё в порядке
agent-drift --fail-over 40     # exit 1, если что-то выше порога — для CI
agent-drift --strict-skills    # ещё и проверить упоминания `/имя` — см. ниже
```

Из коробки понимает `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.cursorrules`,
`copilot-instructions.md`. Остальное — через `--name`.

`--strict-skills` сообщает об упоминаниях `/имя`, за которыми на диске ничего
нет. По умолчанию выключен, потому что честным для всех быть не может: часть
слэш-команд поставляется внутри CLI и не лежит ни в одной папке, так что
переименованный скилл и встроенная команда отсюда выглядят одинаково.
Включайте, если держите все скиллы в репозитории.

## Что ищет

| Сигнал | Что значит |
|---|---|
| `broken_path` | путь не существует нигде — а агент по нему всё равно пойдёт |
| `undocumented_dir` | живая папка, о которой инструкция молчит |
| `template_unused` | правило записано (`notes/YYYY-MM-DD_slug.md`), но по нему ничего не создают |
| `ambiguous_ref` | существует, но не там, где сказано. Не ошибка, просто неаккуратно |
| отставание | не «файл старый», а «проект живёт, а описание нет» |
| `broken_source` | маркер `[источник: …]` ведёт в никуда |
| `stale_unknown` | `[?]` висит дольше 30 дней |
| `unmarked_claim` | цифра-замер вообще без маркера |
| `no_stake_level` | проект не объявил, чего стоят его утверждения |

Балл — **доля протухшего**, а не число ошибок: 40 путей и 7 путей несравнимы.
Шкала: `<20` свежий · `20–39` расходится · `40–59` протух · `≥60` сломан.

## Тезисы протухают тоже

Путь можно сверить с файловой системой. Фразу «медиана охвата 950» — нельзя: у
неё нет адреса, поэтому она стареет молча, а агент продолжает на неё опираться.
Разметка включается по желанию:

```markdown
Медиана охвата 950 [источник: tools/analytics/]
Закон Гудхарта родился из британской статистики [?]
```

`[источник: …]` резолвится теми же правилами, что и любой другой путь — значит
переименованная папка его вскроет. `[?]` — это честное «я не проверил»;
детектор звенит, только когда такое сомнение висит дольше 30 дней.

Насколько файл строг, решает **уровень ставки** в шапке:

```markdown
> Уровень ставки: T2
```

`T0` черновики (утверждения не проверяются вовсе) · `T1` рабочие документы
(умолчание) · `T2` всё, что уходит наружу. Папки-сырьё — `drafts/`, `ideas/`,
`capture/`, `archive/` — всегда T0.

`unmarked_claim` — самый шумный сигнал, и он приглашение, а не приказ:
расставить маркеры на все цифры в репозитории значит изобразить строгость,
которую эта проверка как раз и должна вскрывать.

## Скиллы протухают иначе

Инструкция может быть только неверной. Скилл может ещё и **никогда не
выбраться**, стоить слишком дорого при загрузке или выполнять код, который никто
не читал: это инструкция, приезжающая вместе с shell. Флаг `--skills` проверяет
`SKILL.md` по пяти практикам, на которые ложатся эти отказы:

```bash
agent-drift --skills-only --explain
agent-drift --skills-only --skills-path ~/.claude/plugins    # и установленные
```

| Практика | Сигналы |
|---|---|
| 1 · описание — это триггер | `skill_description_no_trigger`, `skill_description_thin`, `skill_description_vague`, `skill_name_mismatch` |
| 2 · строить из своего опыта | `skill_no_gotchas`, `skill_generic_advice` |
| 3 · тратить контекст экономно | `skill_body_too_long`, `skill_reference_unlinked` |
| 4 · детерминированные скрипты | `skill_script_unlinked`, `skill_script_intent_unclear` |
| 5 · проверить до запуска | `skill_script_reaches_out`, `skill_script_exfil_shape`, `skill_prompt_injection`, `skill_hidden_instruction` |

**Строгость зависит от происхождения.** Свой скилл в своём репозитории
проверяется по всем пяти. Чужой плагин — только на доверие и контекст: с
замечанием «в вашем плагине нет секции с граблями» никто ничего сделать не
может, а совет, по которому нельзя действовать, и приучает пролистывать отчёт.

Две проверки стоит объяснить. `skill_description_no_trigger` звенит, когда
описание говорит, что скилл делает, но не говорит, когда его звать: модели
недо-триггерят, поэтому такой скилл тихо не запускается никогда — а скилл,
который не сработал, не даёт ошибки, которую можно заметить.
`skill_script_intent_unclear` звенит, когда тело упоминает скрипт, но не велит
его **запустить**: прочитанный как справочный материал, он переписывается заново
на каждом прогоне — ровно то угадывание, ради устранения которого его и писали.

Источники: [agentskills.io](https://agentskills.io) — лимиты полей;
[IBM Technology, «5 Best Practices for Building AI Agent Skills»](https://www.youtube.com/watch?v=qYNs80FKIVc)
(10.08.2026) — бюджет ~500 строк и аудит, нашедший дыру у >35% из ~4000
публичных скиллов.

## Почему вся ценность — в ложных срабатываниях

Написать «проверь, что пути существуют» — вечер работы. Первый прогон такой
наивной версии по реальному репозиторию из 11 файлов дал **159 битых путей**.
Почти все — неправда:

- `notes/YYYY-MM-DD_slug.md` — это правило именования, а не файл
- `myrepo/docs/` — путь от имени репозитория, прекрасно резолвится
- `CREATE`, `DROP/TRUNCATE` — SQL-слова в бэктиках
- `myproject/src/main.py` — запись из ASCII-дерева, разобранного без отбрасывания
  корневой строки

Детектор, который 150 раз кричит «волки», выключают после первого запуска и
больше не включают. Поэтому работа ушла не в идею, а в воронку отсева:

1. **Сканируются только размеченные зоны** — бэктики, ASCII-деревья,
   markdown-ссылки. Проза не трогается вообще.
2. **Шаблоны проверяются глобом**, а не как конкретный путь. Шаблон без файлов —
   мягкий сигнал «правило мёртвое», а не битая ссылка.
3. **Каскад баз с тремя исходами**, не двумя: нашёлся где сказано → тишина;
   нашёлся в другом месте → `ambiguous` (вес 0,05); нигде → `broken`.
4. **Деревья разбираются стеком** по колонке отступа, корневая строка блока
   отбрасывается.
5. **Папка, чей родитель уже описан, не считается неописанной** — инструкция
   описывает архитектуру, а не инвентаризирует листья. Вложенный git-репозиторий
   — чужая территория.

Результат на том же репозитории: **8 находок, и все настоящие** — файл,
переименованный месяцы назад, переехавший скрипт, два документа, которых
никогда не было, и `../../` на уровень мимо.

В `tests/` каждый класс ложных срабатываний зафиксирован, чтобы не вернулся.

## Заглушить намеренное

`.drift-ignore` в корне репозитория:

```
# намеренное историческое упоминание — путь мёртв, и в тексте так и написано
~/.config/old-tool/memory

# файл, который мы больше не ведём
skip: legacy/**
```

Коммитится: это часть governance, в отличие от кэша.

**Предупреждение:** если файл растёт, а точность детектора не меняется — значит
фильтры неправильные, и чинить надо код, а не этот список.

## Границы

- Пути в прозе не видны намеренно. Оборачивайте в бэктики.
- Проверяется, **правда ли** написана структура, а не насколько она хороша —
  для качества текста нужен LLM-ревьюер.
- Обход каталогов останавливается на глубине 2 намеренно.
